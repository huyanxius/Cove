# M0 · 外壳骨架 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 一个可运行的 Cove.app：左侧会话侧栏，中间是承载真 `claude` 的终端加原生输入框，顶部是 Agent 状态条，右侧检查器显示任务进度、改动文件和 diff。

**Architecture:** `CoveCore` 是纯逻辑库，把 JSONL 行解析成 `TranscriptEvent`，再由 `SessionSummarizer`（侧栏）和 `ActivityTracker`（状态、任务、改动）消费；输入路由、PTY 注入字节、命令拼装、diff 解析也放在这里，全部单测覆盖。`Cove` 是 App 层，SwiftUI 负责三栏布局，SwiftTerm 的 `LocalProcessTerminalView` 在用户的登录 shell 里拉起 `claude`，`NSTextView` 子类充当输入框。每个打开的会话是一个 `LiveSession`，它持有终端视图和进程，切换会话时不杀进程；同时轮询自己的 JSONL 增量，喂给 tracker。

**Tech Stack:** Swift 6 / SwiftPM、SwiftUI + AppKit、SwiftTerm 1.20、Swift Testing；目标 macOS 14+。

## 已验证的事实

- `claude --session-id <uuid>` 指定新会话 ID；`claude --resume <id>` 恢复时沿用原 ID（只有加 `--fork-session` 才换）。
- JSONL 位置：`~/.claude/projects/<cwd 编码>/<sessionId>.jsonl`。目录名编码有损（`/` 和非 ASCII 都变 `-`），cwd 必须从记录里的 `cwd` 字段取。`subagents/` 子目录不是顶层会话。
- 标题记录：`{"type":"custom-title","customTitle":…}`、`{"type":"ai-title","aiTitle":…}`，同一会话会重复写多次，取最后一条。
- 人类消息：`type=user`、`message.content` 为字符串（或只含 text 块的数组）、`isMeta` 不为真、`isSidechain` 不为真；以 `<` 开头的是本地命令回显，排除。
- 工具调用：assistant 行的 `message.content[]` 里 `{"type":"tool_use","id","name","input"}`，每行通常只有一个块，`message.stop_reason` 为 `tool_use` / `end_turn` / null。
- 工具结果：user 行 `message.content[]` 里 `{"type":"tool_result","tool_use_id","is_error"}`；`TaskCreate` 的结果行带 `toolUseResult.task.id`。
- `TaskUpdate.input` 有 `taskId`、`status`（`pending` / `in_progress` / `completed` / `deleted`）、可选 `subject`。
- `cost-state` 行有 `totalLinesAdded`、`totalLinesRemoved`、`totalCostUSD`。
- `claude` 在用户机器上是 zsh alias（带 `CLAUDE_CONFIG_DIR`），所以必须经 `$SHELL -l -i -c` 拉起，才和用户终端里完全一致。
- CLT 环境跑 Swift Testing 需要 `-F /Library/Developer/CommandLineTools/Library/Developer/Frameworks` 和对应 rpath。

### Task 1: TranscriptEvent 解析

**Files:** Create `Sources/CoveCore/Transcript/TranscriptEvent.swift`；Test `Tests/CoveCoreTests/TranscriptEventTests.swift`

接口：

```swift
public enum TranscriptEvent: Equatable, Sendable {
    case customTitle(String)
    case aiTitle(String)
    case humanPrompt(text: String, timestamp: Date?, cwd: String?, gitBranch: String?)
    case assistant(AssistantBlock, stopReason: String?, timestamp: Date?)
    case toolResult(toolUseID: String, isError: Bool, taskID: String?, timestamp: Date?)
    case cost(linesAdded: Int, linesRemoved: Int, costUSD: Double)
    case other
    public static func parse(_ line: some StringProtocol) -> [TranscriptEvent]
}
public enum AssistantBlock: Equatable, Sendable {
    case text(String), thinking
    case toolUse(id: String, name: String, input: ToolInput)
}
public struct ToolInput: Equatable, Sendable {   // 只保留顶层字符串字段
    public var fields: [String: String]
    public subscript(_ key: String) -> String? { fields[key] }
}
```

`parse` 返回数组，因为一行 user 记录可能带多个 tool_result。

- [ ] 写测试：custom-title / ai-title；字符串 content 的人类消息带出 cwd 和分支；`isMeta` 与 `<command-name>` 开头的消息被排除；带 tool_use 的 assistant 行解析出 name 和 `file_path`；tool_result 行解析出 `tool_use_id`、`is_error` 和 `toolUseResult.task.id`；坏 JSON 返回 `[.other]`。
- [ ] `scripts/test.sh` 确认失败 → 实现 → 通过 → commit `feat(core): parse transcript lines into events`

### Task 2: SessionSummarizer 与 SessionIndexer

**Files:** Create `Sessions/SessionSummary.swift`、`Sessions/SessionIndexer.swift`；Test `SessionSummaryTests.swift`

```swift
public struct SessionSummary: Identifiable, Hashable, Sendable {
    public let id: String
    public let fileURL: URL
    public var title: String
    public var cwd: String?
    public var gitBranch: String?
    public var lastActivity: Date
    public var promptCount: Int
    public var projectName: String { cwd.map { URL(fileURLWithPath: $0).lastPathComponent } ?? "Unknown" }
}
public enum SessionSummarizer {
    public static func summarize(id: String, fileURL: URL, modified: Date, lines: some Sequence<Substring>) -> SessionSummary?
}
public final class SessionIndexer {
    public init(root: URL)
    public func scan() -> [SessionSummary]   // 按 lastActivity 倒序
}
```

标题优先级：最后一条 customTitle > 最后一条 aiTitle > 首条人类消息（压成单行、截 80 字）。没有人类消息也没有标题的会话返回 nil（纯 hook 启动又退出的空会话）。`lastActivity` 取文件 mtime。indexer 只读 `root/*/*.jsonl`，预检行内是否含 `"type":"user"` / `title"` 再做 JSON 解码，缓存键为路径 + mtime + size。

- [ ] 测试：标题三级优先；空会话返回 nil；长消息截断与换行压平；indexer 在临时目录里跳过 `subagents/`、按时间倒序。
- [ ] 实现 → 通过 → commit `feat(core): index sessions from claude project transcripts`

### Task 3: ActivityTracker（状态、任务、改动）

**Files:** Create `Activity/AgentPhase.swift`、`TaskBoard.swift`、`ChangeLog.swift`、`ActivityTracker.swift`；Test `ActivityTrackerTests.swift`

```swift
public enum AgentPhase: Equatable, Sendable {
    case idle
    case thinking(since: Date?)
    case running(ToolActivity, since: Date?)
    case awaitingUser(since: Date?)
}
public struct ToolActivity: Equatable, Sendable {
    public let toolName: String
    public let verb: String      // "Editing" "Running" "Reading" "Searching" "Fetching" "Delegating" "Planning" "Using"
    public let detail: String    // 文件名 / 命令描述 / 模式串 / host
    public static func describe(name: String, input: ToolInput) -> ToolActivity
}
public struct AgentTask: Identifiable, Equatable, Sendable {
    public enum Status: String, Sendable { case pending, inProgress = "in_progress", completed }
    public let id: String; public var subject: String; public var status: Status
}
public struct TaskBoard: Equatable, Sendable {
    public private(set) var tasks: [AgentTask]
    public var completedCount: Int { get }
}
public struct FileChange: Identifiable, Equatable, Sendable {
    public var id: String { path }
    public let path: String; public var editCount: Int; public var created: Bool; public var lastTouched: Date?
}
public struct ChangeLog: Equatable, Sendable { public private(set) var files: [FileChange] }  // 最近改动在前
public struct ActivityTracker: Sendable {
    public private(set) var phase: AgentPhase
    public private(set) var board: TaskBoard
    public private(set) var changes: ChangeLog
    public private(set) var linesAdded: Int, linesRemoved: Int
    public mutating func apply(_ event: TranscriptEvent)
}
```

状态机：人类消息 → thinking；assistant thinking 块或未结束的 text → thinking；tool_use → running（记下待决的 tool id）；该 id 的 tool_result → thinking；text 且 `stopReason == "end_turn"` → awaitingUser。任务：TaskCreate 的 tool_use 先按 tool id 暂存 subject，等结果行带回 `taskID` 才入板；TaskUpdate 改状态，`deleted` 移除。改动：Edit / Write / NotebookEdit 的 tool_use 按 tool id 暂存，结果非错误才记入；Write 且之前没出现过的路径记为 created。

- [ ] 测试：一次完整回合的状态序列；Bash 的 detail 优先用 `description`；TaskCreate → 结果 → TaskUpdate completed 后 `completedCount == 1`；失败的 Edit 不计入；同一文件改两次只占一行、editCount 为 2 并排到最前。
- [ ] 实现 → 通过 → commit `feat(core): derive agent phase, tasks and file changes`

### Task 4: 输入路由与 PTY 注入

**Files:** Create `Input/KeyRouter.swift`、`Input/PasteEncoder.swift`；Test `InputTests.swift`

```swift
public struct KeyStroke: Equatable, Sendable {
    public enum Key: Equatable, Sendable { case up, down, left, right, escape, enter, tab, character(String), other }
    public struct Modifiers: OptionSet, Sendable { shift, control, option, command }
    public let key: Key; public let modifiers: Modifiers
}
public enum KeyRoute: Equatable, Sendable { case composer, terminal([UInt8]) }
public enum KeyRouter { public static func route(_ k: KeyStroke, composerIsEmpty: Bool) -> KeyRoute }
public enum PasteEncoder {
    public static func paste(_ text: String) -> [UInt8]   // ESC[200~ … ESC[201~
    public static let submit: [UInt8] = [0x0D]
}
```

规则：带 ⌘ 的一律归输入框（App 快捷键）。输入框为空时：方向键、Esc、Enter、Tab、⇧Tab（`ESC[Z`）、Ctrl+字母（`& 0x1F`）透传终端；有内容时全部归输入框。编码时把 `\r\n` 规范成 `\n`，剥掉文本里的 `ESC[200~` / `ESC[201~`（防止粘贴内容提前结束 paste 模式），去掉末尾换行。

- [ ] 测试覆盖以上每条规则 + 注入字节精确值 → 实现 → commit `feat(core): route keys between composer and terminal`

### Task 5: 启动命令与 diff 模型

**Files:** Create `Launch/ClaudeLaunch.swift`、`Diff/UnifiedDiff.swift`；Test `LaunchAndDiffTests.swift`

```swift
public enum ClaudeLaunch {
    public enum Mode: Equatable, Sendable { case new(sessionID: String), resume(sessionID: String) }
    public static func claudeArguments(_ mode: Mode) -> [String]
    public static func shellCommand(shell: String, claudeArguments: [String]) -> (executable: String, args: [String])
    public static func shellQuote(_ s: String) -> String   // 单引号包裹，内部 ' → '\''
}
public struct DiffLine: Equatable, Sendable {
    public enum Kind: Sendable { case meta, hunk, added, removed, context }
    public let kind: Kind; public let text: String; public let oldLine: Int?; public let newLine: Int?

```

`shellCommand` 产出 `(shell, ["-l", "-i", "-c", "claude '--resume' '<id>'"])`：`claude` 本身不加引号，让 alias 生效。diff 解析按 `@@ -a,b +c,d @@` 递增行号。

- [ ] 测试：引号转义；resume 与 new 的 argv；diff 行号跟随 hunk 头、`\ No newline` 视为 meta → 实现 → commit `feat(core): build claude launch commands and parse diffs`

### Task 7: 终端与输入框

**Files:** Create `Model/LiveSession.swift`、`Model/JSONLTail.swift`、`Views/TerminalHost.swift`、`Views/Composer.swift`

`LiveSession`（`@Observable @MainActor`）持有一个 `LocalProcessTerminalView`，用 `ClaudeLaunch.shellCommand` 在 cwd 里启动；环境变量在 SwiftTerm 默认之上补 `LANG=en_US.UTF-8`、`COLORTERM=truecolor`。`send(text:)` 先写 `PasteEncoder.paste`，延迟 40ms 再写 `submit`。`JSONLTail` 以 0.5s 周期读文件新增字节，按行切分（保留不完整的尾行），逐行 `TranscriptEvent.parse` 喂给 tracker。

`TerminalHost` 是一个容器 NSView，`updateNSView` 时把当前会话的终端视图换进来，所以切会话不重建视图、不断进程。

`Composer` 用 `NSTextView` 子类：`keyDown` 先判断 `hasMarkedText()`（输入法组字中一律交给系统），再把事件转成 `KeyStroke` 交给 `KeyRouter`；Enter（无 ⇧/⌥）且有内容时提交并清空；⇧↩ / ⌥↩ 插入换行。高度随内容 1–8 行自适应。

- [ ] 打包运行：新建会话、输入中文、⇧↩ 换行、发送、在空输入框下用方向键选权限菜单，逐项手测 → commit `feat(ui): host claude in a pty with a native composer`

### Task 8: 侧栏、状态条、检查器、diff

**Files:** Create `Model/AppModel.swift`、`Model/Git.swift`、`Views/MainWindow.swift`、`SidebarView.swift`、`StatusStrip.swift`、`InspectorView.swift`、`DiffView.swift`、`CoveApp.swift`

`AppModel` 每 5s 在后台线程跑 `SessionIndexer.scan()`；侧栏按 `projectName` 分组，组内按时间倒序，每组默认显示 8 条；运行中的会话带 `PixelDot`。新建会话用 `NSOpenPanel` 选目录，生成 UUID 走 `.new`。

状态条：`PixelDot` + 动词 + detail + 已持续时长，右侧是任务 `PixelProgress`（n/m）与 `+a −r` 行数。检查器分两段：Tasks（当前进行中的高亮）和 Changes（文件名 + 相对目录 + 编辑次数）；点文件在中栏上方以 sheet 形式打开 `DiffView`。`Git.diff(file:cwd:)` 先跑 `git diff --no-color -- <file>`，为空且文件未被跟踪时改跑 `git diff --no-index --no-color /dev/null <file>`；不是 git 仓库时直接给出提示。

- [ ] 打包运行，截图确认三栏、状态随 claude 工作实时变化、diff 着色 → commit `feat(ui): add session sidebar, status strip and change inspector`
